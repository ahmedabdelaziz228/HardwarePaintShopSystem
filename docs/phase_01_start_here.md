# المرحلة الأولى: بداية تنفيذ برنامج محل الحدايد والبوهيات

## الهدف من المرحلة الأولى

المرحلة الأولى هدفها بناء الأساس الذي سيعتمد عليه النظام كله:

- قاعدة البيانات.
- الجداول الأساسية.
- العلاقات بين المنتجات والعملاء والموردين والفواتير.
- تجهيز النظام لاستقبال Desktop App والموبايل بعد ذلك.

هذه المرحلة لا تبدأ بالشاشات، لأن الشاشات لو اتعملت قبل قاعدة بيانات صح هتحتاج تتغير كثير بعدين.

---

## القرار التقني المعتمد

### Desktop App

- C# .NET WPF
- يعمل على Windows Laptop
- هو البرنامج الأساسي للمحل

### Database

- PostgreSQL مثبت على اللاب
- كل الداتا الرئيسية محفوظة عليه

### Local API

- ASP.NET Core Web API
- شغال على اللاب
- تطبيق الموبايل يكلمه عن طريق نفس شبكة الواي فاي

### Mobile App

- Flutter Android App
- يستخدم للبحث، استعلام السعر، العملاء، الجرد، إضافة المنتجات، والمزامنة

## خطوات التشغيل الأولية

### 1. تثبيت PostgreSQL

ثبت PostgreSQL على اللاب.

يفضل استخدام:

- PostgreSQL 16 أو أحدث.
- pgAdmin لإدارة قاعدة البيانات.

### 2. إنشاء قاعدة بيانات

اسم مقترح:

```sql
CREATE DATABASE hardware_paints_shop;
```

### 3. تشغيل ملف SQL

افتح pgAdmin أو استخدم terminal وشغل:

```bash
psql -U postgres -d hardware_paints_shop -f phase_01_database_schema.sql
```

بعد التشغيل، المفروض تلاقي الجداول اتعملت.

## أهم قواعد التصميم

### 1. لا يتم تعديل المخزون مباشرة

أي زيادة أو نقص في المخزون لازم تتسجل في جدول:

`stock_movements`

مثال:

- شراء = حركة موجبة.
- بيع = حركة سالبة.
- مرتجع بيع = حركة موجبة لو المنتج سليم.
- مرتجع شراء = حركة سالبة.
- تالف = حركة سالبة.
- تسوية جرد = موجب أو سالب حسب الفرق.

### 2. لا يتم تعديل الخزينة يدويًا فقط

أي دخول أو خروج فلوس لازم يتسجل في:

`cash_movements`

مثال:

- بيع نقدي = دخول فلوس.
- تحصيل من عميل = دخول فلوس.
- دفع مورد = خروج فلوس.
- مصروف = خروج فلوس.
- سحب صاحب المحل = خروج فلوس.

### 3. لا يتم حذف الفواتير

لو فاتورة غلط، لا تتحذف.

يتم تغيير حالتها إلى:

`void`

مع تسجيل المستخدم والسبب لاحقًا في مرحلة Audit Logs.

### 4. الباركود غير السيريال

الباركود:

- يخص المنتج أو وحدة بيع.
- ممكن يتكرر على نفس نوع المنتج.

السيريال:

- يخص قطعة واحدة فقط.
- لا يتكرر.
- مهم في الضمان والاسترجاع.

## مثال منتج بنظام الوحدات

منتج: معجون حوائط

- الوحدة الأساسية: كيلو.
- وحدة شراء وبيع إضافية: شكارة.
- معامل التحويل: 1 شكارة = 25 كيلو.

في قاعدة البيانات:

- المنتج يتسجل في `products`.
- وحدة كيلو تتسجل في `product_units` بمعامل 1.
- وحدة شكارة تتسجل في `product_units` بمعامل 25.
- أسعار الشكارة والكيلو تتسجل في `product_prices`.
- أي شراء أو بيع يتسجل في `stock_movements` بالكمية المحولة للكيلو.

مثال:

شراء 50 شكارة:

```text
50 × 25 = 1250 كيلو
```

بيع 3 كيلو:

```text
1250 - 3 = 1247 كيلو
```

بيع 2 شكارة:

```text
1247 - 50 = 1197 كيلو
```

## مثال حركة خزينة

بيع نقدي بمبلغ 1500 جنيه:

- يتسجل في `sales_invoices`.
- يتسجل خروج مخزون في `stock_movements`.
- يتسجل دخول فلوس في `cash_movements`.
- يزيد رصيد الخزينة.

بيع آجل بمبلغ 1500 جنيه:

- يتسجل في `sales_invoices`.
- يتسجل خروج مخزون.
- يتسجل مديونية على العميل في `customer_transactions`.
- الخزينة لا تزيد إلا عند التحصيل.
